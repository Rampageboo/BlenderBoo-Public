# v0.7.2 validation

## Result

The 0.7.2 add-on and MCP adapter pass pure Python, headless Blender, schema,
and isolated installed-process checks. The live Blender desktop process was
not replaced or restarted during this validation.

## Exec snapshot

- `diff:none` was checked with `snapshot` patched to raise if called; no
  snapshot was taken, and the receipt reported `detection:disabled`.
- The headless exec exercise passed create/change/delete, exception, edit
  mode, Geometry Nodes input, and FLOAT2 attribute cases after the attribute
  layout fix. No `Array length mismatch` diagnostic remained in that run.
- Default-mode `exec_overhead` p95 in 20-call headless samples:

  | Scene | p95 ms | Budget |
  | --- | ---: | ---: |
  | 1,000 objects | 25.481 | 200 |
  | 10,000 objects | 101.907 | 200 |
  | 1.5M vertices plus 200 objects with materials and nodes | 2.606 | 200 |
  | Edit-mode mesh present | 1.914 | 200 |

- The preserved `orphanage_pre-game-realism_2026-09-26_013200.blend`
  checkpoint was copied to a disposable path and checked with
  `tests/run_python_exec_orphanage_repro_headless.py`. The copy was exactly
  401,860,914 bytes and contained 2,742 objects. A read-only detailed exec
  completed without reproducing the native crash: `changed:false`,
  `detection:detailed`, before snapshot 104,671 ms, after snapshot and diff
  100,178 ms, total exec overhead 204,849 ms. The copied file was removed.
  This is a non-reproduction on the closest pre-crash checkpoint, not proof
  that the original 01:46:22 crash cause is identified. The full scene was
  not rerun after the subsequent FLOAT2 layout correction; a focused FLOAT2
  smoke passed without the earlier array-length diagnostics.
- The default detector can miss arbitrary custom ID properties or other
  changes when the target is neither named literally in the script nor
  reported by depsgraph. `changed:false` remains observational. Detailed
  mode is substantially slower on this scene.

## Runtime and response contracts

- A fake 0.6.4 add-on schema verified that omitted wrapper defaults are not
  sent, an explicitly unsupported field is rejected before dispatch, and
  every available mixed-version receipt carries a restart warning.
- A failed inner Python result was exposed by `operation.status` and counted
  under `python.exec` in `session.call_log_summary`. A first-contact busy
  response retained the running operation ID. Bounded `wait_ms` and bridge
  occupancy behavior passed their unit checks.
- Save write confirmation and disk metadata survived full, default, compact,
  and `toolsets.call` response paths. Fast-capture and contact-sheet glyph
  orientation passed pixel assertions.
