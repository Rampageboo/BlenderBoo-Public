# v0.6.1 Plan: Call Log, Verified Defects, and Detail Blockers

Status: Owner-approved direction, 2026-09-24. Builds on
`docs/v0.6-python-exec-and-lean-responses.md`, which is implemented in the
working tree (not yet committed at the time of writing); build on that state. Names and shapes are proposals; the "Decided" items are not.

## Background

The Owner's recurring complaint: models do not accumulate fine detail. Four
usage reviews exist in the Owner's asset workspace (M4A4 scan/point-cloud
rebuild; School Building 02 interior; Studio interior; M4A4 hard-surface).
They were written **after the fact without per-call records**, so their
timings, call counts, and causal claims are reconstructed and weak.

Two kinds of evidence survive that weakness:

1. **Source-verified defects and gaps** (checked on 2026-09-24 against the
   repository, listed in Part B/C with file references).
2. **Artifacts of external detours.** In all four sessions the agent moved
   geometry generation outside Blender (external Python → OBJ/GLB → import),
   used external xatlas for UV atlases, and processed point clouds externally.
   Round trips lost custom normals and UV seams, and generator scripts
   diverged from the `.blend`, so every refinement forced a re-import. This is
   the most plausible mechanical reason detail does not accumulate, and
   `python.exec` (v0.6) is the main fix.

Note: all four reports argue against arbitrary Python. That position came
from the previous skill text ("intentional safety boundary") and is not an
independent finding. The Owner reversed it in v0.6.

## Part A: automatic call log (highest priority)

Goal: every future session produces a complete, machine-readable record
without the agent having to write one.

### Decided

- Written by the MCP adapter automatically for every call, including each
  step executed inside `workflow.run` / workflow jobs. Not optional per call;
  one global off switch (`CBT_CALL_LOG=0`).
- Local files only. Never sent anywhere.
- Logging failure never fails the tool call (warn once to stderr).

### Record shape (one JSON object per line)

```json
{
  "ts": "2026-09-24T18:35:38.123Z",
  "session": "adapter process id + start time",
  "seq": 42,
  "parent": "workflow operation id or null",
  "tool": "mesh.edit",
  "instance": "port/pid of the target Blender",
  "blend_file": "basename of the active .blend",
  "params_digest": "sha256 of canonical params",
  "params_preview": "first 2 KiB of canonical params JSON",
  "code": "python.exec only: full code up to 64 KiB",
  "ok": true,
  "error_type": null,
  "error_message": "first 500 chars",
  "changed": true,
  "partial_change_possible": false,
  "timings_ms": {"total": 2310, "queue": 40, "blender": 2150, "serialize": 60},
  "response_bytes": {"raw": 36700, "public": 1900},
  "timeout": false
}
```

- `timings_ms.queue` and `timings_ms.blender` require the bridge to return
  its own timings in the envelope (a small `meta.timings` block); the adapter
  computes `total` and `serialize`. Omit fields that cannot be measured
  rather than estimating them.
- On client-side timeout, log `timeout: true`; when the late result later
  arrives or is recovered, append a second record with the same `seq` and
  `"late": true`.

### Location and retention

- Default: `~/.codex/blender-call-logs/YYYY-MM-DD_<session>.jsonl`.
  Override with `CBT_CALL_LOG_DIR`.
- Rotate at 50 MiB per file; delete files older than 30 days on adapter start.

### Summary tool

`scripts/summarize_call_log.py <file-or-dir> [--since]` prints:

- calls per tool, success rate, error types;
- p50/p95/max total and Blender time per tool;
- `python.exec` share of calls and of mutation calls, and the ten most
  frequent exec code shapes (normalize literals, group by first lines);
- timeouts, late results, partial changes;
- bytes returned per tool (raw vs public).

Also expose the same summary read-only as an MCP tool (`session.call_log_summary`)
so an agent can include real numbers in a report instead of reconstructing.

### Acceptance

- Unit tests: record shape, redaction of the bridge token (it must never
  appear, even inside params or code), rotation, retention, workflow parent
  linkage, timeout + late pair.
- A headless run of `tests/run_headless.py` produces a log whose call count
  equals the number of dispatched tools.

## Part C: remove limits that now only add friction

With unrestricted `python.exec`, an allowlist on a typed tool no longer
prevents anything; it only pushes the agent off the typed path and its
preflight. Replace allowlists with validation against Blender's own RNA.

1. **Material node properties.** Add `set_node_property` to `material.patch`
   (parity with Geometry Nodes): any writable RNA property of the node,
   validated by `bl_rna.properties` type, enum items, and range. Add Color
   Ramp element operations (add/remove/set position and color) and curve-map
   points if cheap. Accept any `ShaderNode*` type Blender can instantiate,
   including `ShaderNodeGroup` with a node group reference.
2. **Geometry Nodes.** Accept any node type Blender can instantiate in a
   geometry node tree (check with `bpy.types` / tree `new` and roll back on
   failure), any writable RNA property, and zones (Repeat, Simulation,
   For-Each) if their paired-node creation can be expressed; otherwise
   document exec as the path. Raise the per-patch operation cap from 100 or
   accept dependency-ordered chunked submission.
3. **Modifiers.** Accept any modifier type valid for the object type and any
   writable RNA property (fixes e.g. Bevel `harden_normals` rejection). Keep
   dry-run and confirmation for apply.
4. **`mesh.edit` transform.** Accept an explicit pivot point and an optional
   4×4 affine matrix.
5. **`modifier.apply` on NODES** or a new `object.convert_evaluated`: produce
   a named mesh from the evaluated object (Geometry Nodes, modifier stack),
   optionally keeping the original; report instance realization, materials,
   UV and normal handling.
6. Keep the `workflow.run` step cap for safety but raise it to what the call
   log shows is needed; do not guess.

Each item: a discovery path (`system.capabilities` or the tool's inspect
returns what is accepted) so an agent learns the boundary before building.

## Part D: capabilities that directly carry detail

These exist in Blender but were detoured externally in the reports. Typed
tools are justified because they are long-running, stateful, and easy to get
subtly wrong; exec remains available meanwhile.

1. **Texture baking** (`bake.run`): Cycles selected-to-active and self bake
   for NORMAL (tangent space), AO, DIFFUSE/base color, ROUGHNESS, EMIT;
   explicit source(s), target, UV layer, image (create or existing),
   resolution, margin in pixels, cage object or extrusion + max ray distance.
   Restores render engine and selection afterward. Long-running: must use the
   deferred/operation-ID path (Part E) and write the image to an explicit
   path. Returns output file, coverage (non-empty pixel ratio), and warnings.
   Acceptance: bake a known high-poly bevelled cube onto its low-poly
   counterpart; normal map shows expected edge gradients with correct green
   channel convention.
2. **Smart UV Project** in `uv.unwrap`/`uv.project` with angle limit, island
   margin, area weight; plus a post-check for overlaps, zero-area faces, and
   texel density spread across selected objects.
3. **Seams, sharp, crease, bevel weight** marking in `mesh.edit` (edge
   attributes), since UV quality and subdivision detail depend on them.
4. **PLY import** in `interchange.import` (ASCII and binary), keeping point
   colors and normals as attributes; report counts, bounds, and attribute list.
5. **First save to an explicit path** (`scene.save_as` or a `path` param):
   dry-run, refuse overwrite unless confirmed, verify on disk.
6. **Checkpoint destination**: optional directory and naming template, plus a
   retention preview (list what would be pruned; prune only with confirm).
7. **Render quality settings** in `render.settings`: samples, denoise,
   Eevee raytracing/GI options, color management view/look/exposure. Review
   renders that are flat or washed out hide detail; the agent must be able to
   set up a truthful preview.

## Part E: long operations and reference comparison

1. **Operation IDs for long calls** (render, bake, save, large exec): the
   call returns or can be queried by a stable ID with state
   (queued/running/succeeded/failed), last update, elapsed time, and final
   result; a client timeout never loses the result, and a re-query never
   re-executes. Do not claim cancellation of an in-flight Blender operation.
2. **Reference comparison helpers** (lower priority; exec can do these, so
   only add if the call log shows repeated exec for them): orthographic
   render matching a reference image's camera, silhouette/section extraction
   of a mesh at a plane, and surface distance statistics between two objects.

## Part F: skill and roadmap updates

- `skills/blender-codex-modeling/`: add a short "detail workflow" section:
  block out and match silhouettes/sections against references first, then
  add detail in Blender (exec/bmesh or typed tools) instead of external
  generators, keep one editable source, bake detail last. State that external
  mesh generation is a last resort because it breaks normals, UV seams, and
  identity on every iteration.
- Point the skill at `session.call_log_summary` for any report or retro; a
  report must cite logged numbers, not reconstruct them.
- Rewrite `docs/v0.5-v1-capability-roadmap.md`: remove "without arbitrary
  Python" from acceptance criteria and the "does not expose unrestricted
  Python" boundary; define typed tools as (1) state-safety operations,
  (2) inspection/measurement/verification, (3) long-running or high-frequency
  composites; everything else is exec plus skill recipes, promoted to typed
  tools when the call log shows repetition.

## Part G: response receipts, final shape

v0.6 introduced single-channel output (`CBT_MCP_TEXT_CHANNEL=summary`) and a
compact mutation receipt. Finish it with one rule:

**Return what the agent did not send and needs for its next decision. Never
echo the request. Always return what Blender decided.**

### Required shapes (`default` mode)

| Call | Receipt |
|---|---|
| Mutation, succeeded exactly as requested | `{"ok":true,"tool":"…","changed":true,"state_token":"…"}` and nothing else |
| Mutation, succeeded with deviations | add only the deviation: `renamed_from` / actual `object` name when Blender renamed, `clamped` fields, `changed:false`, non-empty `warnings`, created names that the request did not fix |
| Mutation, failed | `error.type`, `error.message`, `partial_change_possible`, committed/rolled-back/not-executed steps, a resume hint. Detail is worth its cost here |
| Read / inspect | the requested data itself, inline. Size is controlled by field selection, JSON-path selection, and pagination, not by moving small results into an artifact. A single-object query returns only that object (e.g. `light.inspect` with a name must not return the light list) |
| `python.exec` | `result`, `changes` summary, capped stdout/stderr (v0.6 contract) |
| workflow | `ok`, completed/failed step ids, per-step `changed` and deviations only, final `state_token` |

### Remove fixed overhead from every receipt

Current `response_profiles.py` adds to every compacted receipt:

- `original_data_keys` (up to 64 names) and `original_data_keys_truncated`
  (line ~243) — remove;
- a 7-field `response_artifact` object (`artifact_id`, `sha256`, `bytes`,
  `chars`, `tool`, `scope`, `retrieval_tool`) — replace with a single
  `"artifact": "<id>"` string, and only when something was actually omitted
  that is not reconstructible (journal, before/after). An exact-success
  receipt needs no artifact;
- `response_profile` block (line ~325) — emit only in `full` mode or when a
  debug env flag is set.

Also add field / JSON-path selection to inspect tools and to
`response.artifact_get` (return a parseable JSON value, not a character
slice, when a path is given).

### Acceptance

- Byte budget, checked by unit tests on representative envelopes:
  exact-success mutation receipt ≤ 150 bytes; deviation receipt ≤ 400 bytes;
  failures unbounded but without traceback in `default`.
- No field in a receipt equals a value the caller sent (test by feeding the
  request and asserting no echo), except identifiers the next call needs.
- Blender-decided facts never lost: a rename (`Wall` → `Wall.001`), a clamp,
  and `changed:false` each appear in the default receipt.
- Record receipt sizes in the Part A call log (`response_bytes`).

## Suggested order

1. Part A (call log) — so everything after is measurable. Part G next, since
   it changes every call's cost.
2. B1, B2, B5 (verified, small). Reproduce B3, B4, B6; fix what reproduces.
3. Part C items 1, 3, 5 (material properties, modifier RNA, evaluated
   convert), then 2 and 4.
4. Part D 1–3 (bake, Smart UV, edge attributes), then 5–7, then 4.
5. Part E 1.
6. Part F.

## Verification

- Unit tests per item under existing conventions (`tests/test_*_helpers.py`,
  `mcp_server/tests/`); headless runs for B1, B2, C1–C5, D1–D4
  (`tests/run_*_headless.py`).
- `adapter.schema_audit` aligned after every schema change; restart the
  client and make one real typed call.
- Scope of this plan's acceptance ends at the tests above plus a short live
  smoke on Blender 5.2 for each new or changed tool. **Do not** perform asset
  modeling as part of this work.
