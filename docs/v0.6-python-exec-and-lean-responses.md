# v0.6 Plan: Unrestricted Python Execution and Lean Responses

Status: direction approved by the Owner on 2026-09-24. Names and shapes below
are proposals; change them if implementation shows a better contract, but keep
the "Decided boundaries" section.

## Why

1. **Ceiling.** The toolkit exposes only typed tools. When no tool exists for an
   operation, the agent stops or detours (see `docs/reports/`). Current Claude
   and Codex models write competent `bpy`; the 2026-07-16 rejection of an
   arbitrary-Python escape hatch was made when reviewer models approved
   implausible results, and the Owner has now reversed it.
2. **Context cost.** Agents report oversized and duplicated results. Verified
   sources of duplication:
   - `server.py:_profile_mcp_result` returns the same public envelope twice:
     as `TextContent` (mirrored in full up to 16 KiB) and as
     `structuredContent`. Clients that forward both pay twice.
   - Mutation tools repeat their payload inside the envelope. Example:
     `object.create` returns `detail` and again `journal[0].after = detail`,
     plus `object` / `requested_name` / `resolved_name` for one name.
     38 `journal=[...]` sites follow similar patterns.
   - Every result carries transaction scaffolding (`operation_id`, `client_id`,
     `affected_datablocks`, `warnings` inside `data` and at the top level).

## Decided boundaries

- Python execution is **unrestricted**: no AST filtering, no import allowlist,
  no sandbox. Full `bpy`, `bmesh`, `mathutils`, standard library.
- Execution runs on Blender's main thread through the existing bridge queue,
  under the existing authentication, instance lease, and `expected_state`
  checks. The loopback-only, token-authenticated bridge is unchanged; exec
  does not widen the network surface.
- Typed tools remain and are not removed. Guidance changes from "typed only"
  to "typed where it exists and fits; Python otherwise". No capability-gap
  report is required merely for using exec.
- Recovery is by change evidence and checkpoints, not by restriction.
- No automatic retry of an exec call after timeout or transport failure (same
  rule as other mutations).

## Part A: `python.exec`

### Contract (executor may refine names/shapes)

Input:

- `code` (string, required). Runs as a module body in a fresh namespace
  pre-populated with `bpy`, `bmesh`, `mathutils`, `Vector`, `Matrix`, `C`
  (`bpy.context`), `D` (`bpy.data`).
- `result` convention: if the code assigns a variable `result`, its
  JSON-serializable value is returned. Non-serializable values are converted
  with `repr` and flagged.
- `expected_state` (optional), `checkpoint` (optional bool / tag: save a
  checkpoint before running when the file has a path), `diff` (default
  `"summary"`; `"none"` | `"summary"` | `"detailed"`), `timeout_hint_s`
  (informational; see Risks).

Output (`data`):

- `result`, `stdout`, `stderr`: each capped (suggest 8 KiB inline; overflow
  goes to the response artifact and the receipt shows `truncated: true`).
- `changes`: a before/after comparison of `bpy.data` computed around the
  call — per datablock collection (objects, meshes, materials, collections,
  node groups, images, actions, …) the created, removed, and renamed names,
  and for objects a cheap modified signal (transform, parent, collections,
  modifier stack, mesh vertex/face count, material slots). `summary` returns
  counts plus up to N names per category; `detailed` returns field-level diffs.
- `changed`, `state_token`, `checkpoint` (path if taken).
- On exception: `ok: false`, error `type`/`message`, traceback trimmed to the
  frames inside the user code, and **still** `changes` and `stdout` captured
  up to the failure, with `partial_change_possible: true` when `changes` is
  non-empty.

State handling: always `bump_epoch()` after exec unless `changes` is provably
empty, and return the new `state_token`. Register in its own toolset
(`python`), exposed both directly and inside `workflow.run`.

### Also consider (executor decides)

- `python.eval` for a single expression, read-only by convention, to replace
  many small `inspect` calls cheaply.
- Pushing an undo step (`bpy.ops.ed.undo_push`) before exec, only if it can be
  shown to work from the timer context; otherwise rely on checkpoints.

### Risks the implementation must handle

- **A hung script blocks Blender's main thread** and the bridge cannot
  interrupt it. The pending timeout will return, but the work continues.
  Document this; do not claim cancellation. The bridge must report the call
  as possibly still running, not failed.
- **GPU calls from the timer crash Blender** (`05-risks-and-gotchas.md`).
  Exec cannot prevent a user script from calling `render.opengl` or
  `GPUOffScreen` inside the timer. Detect obvious cases and return a warning
  with the safe alternative (the deferred screenshot/render tools); do not
  block.
- **`wm.open_mainfile` / `wm.read_homefile` / add-on reload** from exec
  invalidates bridge state. Detect filepath/epoch change after the call and
  reconcile; return a warning.
- **Operator context.** Many `bpy.ops` fail without a window/area override.
  Provide a helper in the namespace (e.g. `view3d_override()`) that yields a
  valid `temp_override` context.
- The 1 MiB request limit bounds script size; that is fine.

## Part B: lean responses

Goal: one copy of each fact, and a default receipt that fits the common case.

1. **Single channel.** Stop mirroring the full envelope into `TextContent`
   when `structuredContent` is present. Measure first which channel each
   target client (Claude Code, Codex) actually forwards to the model, then
   emit exactly one full copy on that channel and a one-line text summary on
   the other. Make the choice configurable (`CBT_MCP_TEXT_CHANNEL=summary|full`)
   with the measured-correct default.
2. **Remove in-envelope duplication at the source.** For mutation tools,
   drop `journal[*].after` when it equals a top-level field (return a
   reference instead), collapse `object`/`requested_name`/`resolved_name`
   to `object` plus `renamed_from` only when they differ, and omit empty
   `warnings`, `null` `client_id`, and `affected_datablocks` that repeat the
   object name. Keep `journal` available in `full` mode.
3. **Default receipt shape.** In `default` mode, a successful mutation
   returns: `ok`, `tool`, `changed`, `state_token`, affected names, created
   names, warnings, and the artifact reference when anything was omitted.
   Reads keep their data but honor pagination and field selection.
4. **Instance identity once.** Return instance identity on selection and on
   change, not on every result.
5. Keep the existing artifact store and `response.artifact_get`; they are
   the exact-recovery path for anything omitted.

Acceptance for Part B is measured, not asserted: record bytes and approximate
tokens for a fixed set of representative calls (`scene.inspect`,
`object.create`, `mesh.inspect`, `modifier.add`, `architecture.wall_build`
dry-run, `workflow.run` with 8 steps, `python.exec` creating 50 objects)
before and after, in both clients.
