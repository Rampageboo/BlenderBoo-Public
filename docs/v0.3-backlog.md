# Codex Blender Toolkit v0.3 Backlog

This backlog is evidence-driven from the first live v0.2 loop on the dense shrub:
`review -> checkpoint -> repair -> render comparison` on Blender 5.1.2.

## Live-loop evidence

- Typed `scene.inspect` summarized a 3,593-object scene and paged names.
- Typed `render.preview` produced fixed-camera 1280x720 before/after renders.
- Typed `checkpoint.save` created checkpoint index 2 without overwriting prior state.
- The repair could not be expressed through any v0.2 typed tool. The community
  Blender MCP arbitrary-Python channel was required to add a backface-specific leaf
  shader to three V5 materials.
- Typed post-repair inspection confirmed object/type counts were unchanged.
- The repaired scene was saved separately as
  `SM_DetailedShrub_HemisphereDenseV5_ReviewBackface_v01.blend`.
- 218,864 pixels differed by more than 8 RGB levels between renders (23.748% of the
  1280x720 image). Near-black leaf backs became readable dark-green undersides without
  changing geometry.

## P0 — make a typed repair loop possible

1. `material.inspect`
   - Material users, node summary, relevant Principled inputs, output links, and
     collection/object scope.
   - Bounded output and filters by material/object/collection.
2. `material.patch`
   - Allowlisted operations rather than arbitrary Python: set socket default, add or
     remove a named node, connect/disconnect named sockets, and set material flags.
   - `dry_run`, expected-before preconditions, affected-user count, idempotent node
     names, and a structured before/after journal.
3. `scene.save_version`
   - Non-overwriting save-as with base name/tag, automatic sequence allocation, and
     returned absolute path. Preserve the current checkpoint relationship.
4. Transaction metadata
   - Operation id, checkpoint id, affected datablocks, before/after values, warnings,
     and a clear `changed` flag in every mutation result.

## P1 — make review evidence first-class

1. `render.review_set`
   - Fixed camera plus top/side/three-quarter presets, collection visibility overrides,
     and one manifest tying view settings to output paths.
2. Return MCP image content or resource links from preview tools, not only local paths.
3. `render.compare`
   - Validate matching dimensions/camera metadata; return changed-pixel count, mean
     absolute RGB delta, bounding box, and optional side-by-side/diff artifact.
4. Extend `scene.inspect`
   - Filters for name prefix/regex, type, collection, material, visibility, custom
     properties, and material usage. Report saved/dirty state and current file path.

## P1 — shrub structural audits

1. `curve.audit_connectivity`
   - Collection-scoped spline root-to-parent distance, hierarchy rules, thickness
     thresholds, bounded offenders, and dense Bezier sampling.
2. `leaf_cluster.audit_alignment`
   - Owner-tip gap, terminal-tangent versus growth-axis angle, retained twist, and
     bounded offenders.
3. Audit tools should create markers only through explicit opt-in and use standardized
   `ISSUE_*` names/custom properties.

## P2 — transport and schema hardening

1. Generate MCP tool schemas from one authoritative registry definition; the current
   FastMCP signatures duplicate add-on schemas and can drift.
2. Add request ids and idempotency keys so reconnect/retry cannot duplicate mutations.
3. Add progress reporting for render and long audits. A call that has started on
   Blender's main thread remains non-cancellable unless the operation itself supports
   cooperative cancellation.
4. Add Blender UI controls to generate/rotate a transient token and start/stop the
   loopback bridge, without persisting or displaying it in logs.

## Acceptance target for v0.3

Repeat this exact shrub loop without the community arbitrary-Python tool: inspect the
three leaf materials, save a checkpoint, dry-run and apply the backface shader patch,
save a new version, produce a review set, and return a structured image comparison and
operation journal entirely through `codex-blender` typed tools.
