# Codex Blender Toolkit v0.5-v1.0 Capability Roadmap

Owner-approved direction (2026-07-14): expand the toolkit beyond the current
review/material-repair vertical slice so Codex can reliably perform most
practical Blender-native production workflows through typed, inspectable,
recoverable tools.

The target is broad practical control, not a one-to-one MCP wrapper for every
`bpy` function. `python.exec` supplies custom and bulk Blender work. Promote a
pattern to a typed tool when it needs (1) state safety or rollback, (2)
inspection, measurement, or verification, or (3) long-running coordination or
frequent composition. Use the automatic call log to show repetition before
adding another convenience wrapper. Keep recipes in the modeling skill.

Owner priority update (2026-07-17): modeling is the highest product priority.
Complete the general polygon-modeling, hard-surface, and retopology slices before
starting the planned production-render expansion. Existing preview/review rendering
remains supported; the v0.7 rendering track stays on the roadmap but is not the next
implementation target.

## Sequencing

Finish the remaining v0.4 coordination work first:

1. Phase 2: document leases, fairness, and explicit backpressure.
2. Phase 3: multi-instance registry/routing and the native bridge Start/Stop UI.
3. Prove two live Blender instances cannot be confused or silently clobber one
   another before substantially expanding the mutation surface.

Capability work then proceeds in vertical slices. Each release must include
inspection, guarded mutation, validation, recovery, typed MCP schemas, unit
tests, Blender headless coverage, and at least one live GUI workflow.

The v0.6.1 call log supplies evidence for later prioritization. The current
`workflow.run` cap remains 32 steps until observed sessions justify changing
it. Reference matching, section extraction, and surface-distance helpers
remain `python.exec` recipes until repeated logged use warrants typed tools.

## v0.5 — Scene and object foundation

- Inspect/filter objects and collections by name, type, hierarchy, visibility,
  selection, material, and custom properties.
- Annotation review feedback (completed 2026-07-19): bounded read-only inspection
  of native Annotation datablocks, layers, frames, strokes, and point coordinates,
  with screenshot pairing for visual interpretation.
- Create, duplicate, rename, link/unlink, parent/unparent, hide/show, and delete
  objects and collections.
- Read and patch transforms with local/world-space choice and explicit
  before/after values.
- Inspect and manage cameras, lights, world assignment, active camera, and basic
  render settings.
- Add general destructive-action confirmation and transaction journals for
  deletion, unlinking, and hierarchy changes.

Acceptance: build and revise a small staged scene, render a review set, compare
the result, and save a new version with observable state and recovery evidence.

## v0.6 — Geometry, curves, modifiers, and Geometry Nodes

- Bounded mesh inspection: counts, bounds, attributes, material slots, manifold
  and topology summaries.
- Typed mesh operations using `bmesh` where practical: primitive creation,
  selection by predicate, transform, extrude/inset/bevel/subdivide/merge/delete,
  normals, and validation.
- P0 modeling core: bounded local/world measurement; semantic boundary,
  non-manifold, connected, sharp, coplanar, length/area/valence, loop, and ring
  selection; and atomic dissolve/fill/bridge/bisect/triangulate/symmetrize chains.
- P0 modeling workflows: recoverable native Join and loose/material/semantic
  Separate with target/source identity guarantees, deterministic names, result
  budgets, and rollback; plus atomic local-axis align, even distribution, and
  grid/point/plane snap.
- P0 topology precision (completed 2026-07-17): viewport-independent true loop cut
  over one complete quad edge ring plus signed, direction-disambiguated edge slide in
  the same dry-run-first atomic `mesh.edit` transaction.
- P0 workplane precision (completed 2026-07-17): stateless face/edge-derived or
  explicit orthonormal U/V/N frames with exact projection, alignment, and increment
  snapping inside the same atomic mesh transaction.
- P0 topology construction (completed 2026-07-17): exact same-face vertex connect,
  rail-validated quad Grid Fill, face Poke, and viewport-independent plane Bisect as
  the deterministic headless Knife path, all inside the guarded mesh transaction.
- P0/P1 selection and object-workplane follow-up (completed 2026-07-18): deterministic
  bounded shortest paths, predicate-constrained region growth, and dry-run-first
  object placement on face-derived or explicit reference-object workplanes.
- P1 spin/screw follow-up (completed 2026-07-18): local-axis BMesh spin and
  total-travel screw extrusion/duplication with pre-allocation result bounds,
  guarded full-revolution seam merge, automatic axis welding, dry-run journals,
  and atomic rollback.
- Remaining P1 follow-up: broader dependency-aware Join/Separate inputs beyond
  the current guarded plain-source or keep-source contracts.
- P1 hard-surface modifier foundation (completed 2026-07-17): typed Boolean,
  Shrinkwrap, Simple Deform, Curve, Lattice, Remesh, Screw, and Displace contracts,
  compatible datablock-reference validation, typed field rollback, and bounded
  Remesh/Screw preflight estimates.
- P1 hard-surface workflow foundation (completed 2026-07-17): immutable bounded
  `panel_inset_v1`, `boolean_opening_v1`, `support_loop_pair_v1`, and
  `mirror_array_v1` templates with optimistic state tokens, mesh-edit confirmation,
  Mirror-to-Array state chaining, and exact modifier-removal compensation.
- Remaining P1 hard-surface follow-up: richer parametric panel/opening variants and
  production-asset live qualification.
- P1 retopology/organic follow-up: surface projection, voxel remesh, edge-flow and
  quad-quality diagnostics, then separately gated sculpt/mask operations once their
  view/context and recovery contracts are proven.
- Curve/spline inspection and guarded editing, including connectivity and
  alignment audits generalized from the shrub test bed.
- Inspect/add/configure/reorder/apply/remove modifiers validated through Blender RNA.
- Inspect and patch Geometry Nodes node groups, interfaces, nodes, links, and
  modifier inputs with stable names and preconditions.

Acceptance: create or materially revise both a hard-surface asset and a procedural
asset; measure and semantically target their geometry; verify topology,
dimensions, symmetry, and dependency-graph results; and recover from a rejected or
failed edit using typed tools and `python.exec` where appropriate.

## v0.7 — Look development, UV, rendering, compositing, and interchange

- UV-layer inspection plus guarded unwrap/project/pack and UV transform tools.
- Extend material operations to textures, images, mapping, material slots, and
  reusable node-group workflows.
- Full camera/light/world inspection and patching, including color management
  and bounded render-engine settings.
- Inspect and patch compositor node graphs; produce structured render manifests
  for passes and outputs.
- Add an explicit production-render surface separate from bounded previews:
  still and frame-range execution, exact output paths, overwrite refusal,
  engine-aware resolution/sample/time budgets, progress reporting, cooperative
  between-frame cancellation, and postflight verification of every artifact.
- Expose typed Cycles and Eevee quality controls without silent fallback,
  including sampling, denoising, light-path limits, film/transparency, motion
  blur, depth of field, and available render-device discovery/selection.
- Build reusable lighting workflows for camera/light rigs, HDRI environments,
  and IES profiles with explicit external-file validation and color-space
  handling.
- Support production passes and outputs: AOVs, Cryptomatte, multilayer EXR,
  view-layer pass configuration, compositor File Output slots, and collision-
  checked delivery manifests.
- Add render diagnostics for missing cameras or textures, unsupported nodes,
  color-management mismatches, invalid output paths, estimated pixel/frame
  cost, and common noise/firefly/performance risks.
- Extend visual iteration beyond a single preview: controlled variants,
  contact sheets, image comparisons, and machine-assisted review evidence,
  while leaving subjective style selection and final aesthetic approval to the
  Owner.
- Guarded import/export for core formats such as OBJ, FBX, glTF, USD, and
  Alembic, with explicit paths, option schemas, overwrite rules, and postflight
  validation.

Acceptance: import an asset, perform a look-development and lighting pass,
render/compare evidence, execute a collision-safe production still and bounded
frame sequence, validate all declared passes/outputs, recover cleanly from a
cancelled or failed render, export a validated deliverable, and preserve the
source document through checkpoint/version controls.

## v0.8 — Rigging and animation

- Inspect/create/edit armatures and bones with mode/context restoration.
- Inspect and patch parenting, constraints, vertex groups, weights, and skinning.
- Create/read/update keyframes, F-curves, actions, NLA tracks, drivers, and shape

- Add animation-range, dependency, missing-target, and deformation validation.

Acceptance: rig and animate a bounded test asset, render deterministic review

## v0.9 — Workflow orchestration and extensibility

- Compose typed operations into resumable, idempotent jobs with progress,
  cooperative cancellation, operation IDs, and structured manifests.
- Add batch scene/asset processing without allowing one failure to leave later
  files or instances in ambiguous state.
- Add queued multi-camera, multi-frame, and multi-instance render jobs with
  explicit instance attribution, per-frame progress, resumable frame
  boundaries, bounded result retention, and no claim that an in-flight Blender
  frame can be interrupted safely.
- Integrate Blender asset libraries and reusable presets/templates.
- Define an extension-adapter contract for selected third-party add-ons.
  Extensions declare schemas, required context, side effects, validation,
  and rollback/recovery behavior. `python.exec` remains available for direct
  Blender and add-on scripting.
- Eliminate schema duplication by generating or automatically cross-checking the
  MCP adapter against the Blender-side registry.

Acceptance: execute a multi-asset job across multiple Blender instances with
clear per-instance attribution, progress, partial-failure reporting, and safe
retry.

## v1.0 — Production graduation

v1.0 is reached when the supported workflow matrix, rather than Blender's entire
API surface, is demonstrably reliable:

- Common scene assembly, modeling, Geometry Nodes, look-development, UV,
  lighting, rendering, compositing, animation, and import/export workflows are
  possible through an appropriate mix of typed tools and `python.exec`, with
  recorded evidence of the result.
- Representative Cycles and Eevee projects can complete typed preview,
  production-render, AOV/EXR delivery, comparison, cancellation/recovery, and
  versioned-save workflows without path collisions or silent device/setting
  fallback.
- Every supported mutation has typed input, preflight or dry-run where useful,
  optimistic state protection, transaction metadata, explicit destructive
  confirmation, and a documented recovery path.
- Blender 5.x and at least one supported Blender 4.x line pass the declared unit,
  headless, and live-GUI compatibility matrix.
- Multi-client and multi-instance tests prove that calls fail loudly on stale
  state, lease contention, overload, or ambiguous instance selection.
- At least three materially different real projects complete end-to-end typed
  workflows and expose no unresolved data-loss or wrong-target defect.

## Safety and product boundaries

- Keep `bpy` execution serialized on Blender's main thread.
- Preserve the established workflow where applicable:
  `inspect -> dry-run/preflight -> expected_state -> checkpoint -> apply ->
  validate -> render/compare -> save_version`.
- Destructive or hard-to-reverse operations require explicit confirmation and
  must report affected datablocks before execution.
- Tools that depend on Blender mode, selection, active object, frame, camera, or
  editor context must snapshot and restore that state or fail before mutation.
- `python.exec` exposes unrestricted Blender Python with the same instance,
  state, checkpoint, and postflight discipline used for other mutations.
- UI-only or third-party functionality is supported through explicit adapters
  when it can meet the same observability and recovery contract; unsupported
  features must fail clearly rather than pretending success.

## Planning range

These are planning ranges, not delivery commitments. They assume sustained
single-track development with regular real-Blender validation:

- Complete v0.4 Phase 2/3: approximately 2-4 weeks.
- Reach reliable common scene/object/material/render control through v0.6-v0.7:
  approximately 2-3 months after v0.4.
- Reach broad asset, Geometry Nodes, UV, interchange, rigging, and animation
  coverage through v0.8-v0.9: approximately 4-8 months total.
- Production-graduate the supported workflow matrix as v1.0: approximately
  6-12 months total, depending on Blender-version coverage and live-project
  findings.

"Every Blender function and every third-party add-on" has no finite completion
date. The durable product goal is reliable coverage of most real workflows plus
a safe, typed path for extending the remainder.
