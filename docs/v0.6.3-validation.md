# v0.6.3 validation

Date: 2026-09-24. Target: Blender 5.2.2 on Windows. The headless and GUI
qualification used isolated Blender processes and test scenes; the Owner's
open Blender document was not changed.

## Behavior and performance

- `assembly.analyze` passed gap, contact, 2 mm overlap, tube-end overlap,
  parented-pair, and evaluated-versus-base fixtures. A pair of roughly
  200,000-triangle meshes completed in 0.723 s. Distances and penetration
  remain bounded-sample estimates; a transverse crossing can have an unknown
  depth when no sample lies inside either part.
- `scene.fast_capture` used the deferred viewport draw path. Isolated GUI
  bridge round-trip medians were 223.734 ms (`scene.screenshot`, 512 px),
  564.597 ms (screenshot, 1024 px), 232.176 ms (fast capture, 512 px), and
  550.648 ms (fast capture, 1024 px). The 512 px fast capture met the 500 ms
  target. Its median draw and PNG-write phases were 151.317 and 7.902 ms.
  The first 512 px screenshot incurred a 2263.288 ms warm-up. Three views
  produced one sheet; two concurrent clients succeeded and viewport settings
  were restored. Local machine-readable evidence is
  `tests/.tmp_gui_fast_capture/result.json`.
- `render.background` rendered a never-saved red scene and a green material
  edit made after saving a red baseline. Both 64 x 64 outputs reflected the
  snapshot, not the baseline. Cancellation ended the child process and
  reported `cancelled`.

## Deployment

The 0.6.3 ZIP was installed to Blender 5.2, with the old add-on and Codex
skill backed up under `dist/installed-backups/v0.6.3-20260924-210207/`.
The Codex and Claude skill copies now contain the short skill and agent
metadata, without the removed reference or script directories. Their
`SKILL.md` hashes match the repository source. The Codex copy's local
`learning.jsonl` hash matched its backup exactly; the Owner's data was kept.

`tests/run_installed_deployment_headless.py` passed in a fresh Blender 5.2.2
process. It imported the installed add-on from `%APPDATA%`, imported the
adapter from the configured repository `PYTHONPATH`, and reported version
0.6.3 from both. `system.doctor` was healthy, `python.exec` returned 42,
and `adapter.schema_audit` reported 147 tools with zero errors or warnings.
The call log was present without the bridge token. Local evidence is under
`tests/.tmp_deployment_verify/`; its call-log count of 14 includes earlier
smoke runs in that reused directory.

Fresh Codex and Claude Code eager-mode tool deferral and initial context
usage remain unmeasured. Bounded, read-only CLI probes (`codex exec
--ephemeral --json --sandbox read-only` and `claude -p --output-format json
--no-session-persistence --permission-mode plan`) timed out after 90 s and
45 s respectively without usage records. Both processes were stopped. The
147-tool schema count is not evidence of client-side deferral, so no client
was switched to `CBT_MCP_TOOL_MODE=search`. No client configuration changed.

The already-running Blender and MCP processes keep loaded code until restarted.
